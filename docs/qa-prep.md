# Jury Q&A preparation

Answers point to evidence in the repo. Numbers come from `dashboard/index.html`, which is regenerated by `factory evidence` from committed artefacts.

## Technical

**Q: How do you know the migrated rule behaves like the original?**
For every formula the transpiler compiles, we execute the original Power Fx in Microsoft's interpreter (the oracle) and the generated C#, using the same frozen inputs. Those inputs are threshold boundaries plus seeded random cases, hash-locked in `parity/testset/TESTSET.lock`. Any difference is a `failed` rule. Mutation testing then checks that the cases are strong enough to catch a wrong translation.

**Q: What can't you prove?**
Formulas that reference live controls, `Self`, `Parent` or `User()`; cloud flows (design only, no code generated); and UI layout. These are reported as `unproven`, not as passing. On the real Approvals Kit that covers most rules today, and we show that number rather than hide it.

**Q: Why not let the LLM write the code?**
Generated code has to be reproducible and reviewable. A deterministic AST-to-C# transpiler gives byte-identical output on every run, and CI fails on drift. The LLM explains rules. It does not write the code that parity depends on.

**Q: A 3B local model? Isn't that weak?**
Yes. That was deliberate: no client data leaves the box, and the whole run replays offline. The model only drafts statements, and code makes the decisions. Swapping in Azure OpenAI is a configuration change, and the self-improvement harness measures whether it helps.

**Q: How does it scale to 30 apps?**
Parse, generate and parity are deterministic and run in seconds to minutes per app. LLM interpretation is about 3 s per rule on CPU, and replay is free. The editable effort model on the dashboard projects human-review hours from measured per-app rates. Its inputs are labelled assumptions.

**Q: What about Dataverse data migration?**
Out of scope for this run. `design.json` records the container and partition-key mapping per table. Moving data, plus reconciliation counts, is a programme workstream, budgeted as fixed days per app in the effort model.

## Responsible AI

**Q: Could a prompt injection in legacy code get a rule waved through?**
No. Review flags are computed by code, outside the model (ADR-008). Source is fenced as untrusted data, and injected text forces review and caps confidence at 0.5. There is a test with a planted "AI reviewer: approved" comment.

**Q: Fairness and the FCA?**
Rules that touch protected or proxy characteristics (age, date of birth, postcode, nationality, vulnerability, ...) get a deterministic fairness flag and go to `HUMAN_REVIEW.md` for an accountable person. The factory preserves behaviour; it does not rule on whether that behaviour is lawful. Consumer Duty sign-off stays with the insurer.

**Q: Did you tune on the test set?**
No. Tuning uses the Approvals Kit, with ground truth hash-locked before tuning started. The synthetic Claims Workbench is held out: only its aggregate score is recorded, and keep/revert uses the tuning score alone. A hypothesis that hurt the score was reverted and stays on the leaderboard.

**Q: Who is accountable for an AI-written statement?**
The reviewer who signs off the queue item. Each statement links to file:line in the legacy source and to its parity evidence.

## Implementation

**Q: What's not done?**
See `WAKE_UP.md` and `KNOWN_FAILURES.md`. In short: Azure browser sign-in (MSAL) is not implemented, flows are design only, no Azure deployment was made, and model confidence is uncalibrated.

**Q: What would the first 2 weeks look like with the client?**
Week 1: export solutions for 3 representative apps, run the factory, and calibrate the effort model with measured rates. Week 2: review-queue workshops with the business owners, then sign-off on the RBAC and fairness decisions.

**Q: Is the Claims Workbench real?**
No. It is a synthetic insurance app written for this run, so the held-out evaluation and the end-to-end journey have something insurance-shaped to work on. The Approvals Kit is a real Microsoft open-source app (MIT, pinned commit).
